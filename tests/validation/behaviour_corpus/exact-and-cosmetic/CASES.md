# Corpus: exact-and-cosmetic (Type-1 clones + negative controls)

All code hand-written for this corpus. Each case has `left/` (A, "original") and `right/` (B, "accused").
Generator for mechanically derived files: `../../mkcorpus.py` (scratchpad root).

| Case | Files | Transformation (left -> right) | Expected outcome (fair, explainable tool) |
|---|---|---|---|
| 01_identical | inventory.py (117 L), pricing.js (63 L) | Byte-identical copies (shutil.copyfile). | Line ratio 1.0, 0 add/del; deep Jaccard 1.0 in every mode; SHA-256 identical. |
| 02_whitespace_java | OrderService.java (108 L -> 134 L) | Same tokens. K&R braces -> Allman braces, 4-space indent -> tabs, spaces inside parentheses `( x )`, three long expressions wrapped onto continuation lines, `} else {` split. No identifier/literal/comment change. | Token-based deep channel: Jaccard ~1.0 (token stream identical). Line channel: ratio expected to drop substantially (almost every line textually changed) unless whitespace normalization helps; tool should make clear the line ratio is a textual measure. |
| 03_comments_c | ringbuf.c (141 L -> 137 L) | Only comments changed: block file header replaced with `//` copyright header, inline field comments removed, function comments reworded and switched `/* */` -> `//`, some new comments added, one inline comment moved to another line. Code tokens identical. | With --strip-comments: line ratio ~1.0 (modulo blank-line drift) and deep Jaccard ~1.0. Without stripping: deep Jaccard high but < 1 (comment words are tokens); line ratio moderately high. |
| 04_blanklines_js | router.js (108 L -> 147 L) | All original blank lines removed, then a blank line inserted after every line ending in `{`, plus 3 blank lines before each method/class/function header. Non-blank lines byte-identical and in same order. | Deep Jaccard 1.0 in all modes (blank lines carry no tokens). Line ratio should stay high; ideally additions/deletions count only blank lines. |
| 05_crlf_python | csvstats.py (116 L both) | Right file converted LF -> CRLF. Nothing else. | Line ratio 1.0 and deep Jaccard 1.0 (line-ending change is not a content change). SHA-256 differs (expected, and should be the only difference). |
| 06_combined_go | ratelimit.go (123 L -> 130 L) | Tabs -> 4 spaces, struct-field and composite-literal alignment collapsed (`tokens   float64` -> `tokens float64`), trailing field comments removed, doc comments removed/reworded/added, `//` package doc -> `/* */` block with copyright, blank lines doubled between decls, blank lines inside AllowN removed. | Deep Jaccard ~1.0 with --strip-comments; still high without. Line ratio moderate (indent changed on most lines). |
| 07_unrelated_python | core.py: inventory module (117 L) vs Markov text generator (98 L) | Negative control: different programs, both Python 3 with typing/dataclass-style idioms, same file name. | Line ratio low; deep Jaccard near 0 in raw mode. Under --normalize, any score must stay below the calibrated threshold (93) or be flagged; no high-similarity claim. |
| 08_unrelated_java_boilerplate | Entity.java: Customer DTO (99 L) vs Shipment DTO (101 L) | Negative control/trap: independently written POJOs; different fields and packages but identical idiom (getter/setter, equals/hashCode/toString). | Raw Jaccard low-to-moderate (shared idiom tokens like `public boolean equals(Object o)` block). Under --normalize, scores will likely be high because getters/setters normalize to identical shapes; tool should NOT present this as copying - should be below the 93 threshold or clearly disclosed. Line ratio moderate due to structural lines (`}` , `return`, `@Override`). |
| 09_blanklines_large_autojunk | warehouse.py (231 L -> 292 L) | inventory + csv-stats merged into one module (>200 lines so difflib autojunk is active); right doubles every blank line and adds a blank after each `def`. | Deep J 1.0; line ratio should not be distorted by autojunk; extra profiles `noautojunk`, `nws_noautojunk` (summary09.tsv). |

Profiles run per case (`r_<profile>.json`, `log_<profile>.txt`):
`default`, `simple` (`--mode simple`), `strip` (`--strip-comments`), `nws` (`--normalize-whitespace`),
`nws_strip_word` (`--normalize-whitespace --strip-comments --by-word`), `norm` (`--normalize`),
`strip_norm` (`--strip-comments --normalize`), `strip_norm_la` (`--strip-comments --normalize --lang-aware`).
